# drawsrv

把 Excalidraw 画布保存在自己的服务器上，在电脑、平板之间接着画。

drawsrv 面向个人使用，也适合资源有限的小型 VPS。它提供多画布管理、自动保存和跨设备同步，并用 Git 留下修改历史。

- 在主页新建、搜索、打开和删除画布，最近修改的画布排在前面。
- 同一个画布可以在多台设备上打开，内容自动同步，缩放和滚动位置各自保留。
- 支持图片、素材库，以及 `.excalidraw` 文件的导入和导出。
- 自动记录历史，之后可以在服务器上用 Git 查看。

## 如何使用

打开主页，新建画布即可开始绘图。修改会自动保存；主菜单提供重命名、手动保存和文件导入导出。界面按浏览器语言偏好选择英语或简体中文，没有匹配时使用简体中文。

多端修改发生冲突时，页面会提示处理。先导出本地备份，再刷新查看服务器上的内容。

### 删除与回收站

主页列表行悬停时显示删除图标，按住 2 秒、环形进度走完后移入回收站；松开或移出按钮取消。触屏上图标始终显示，键盘聚焦后可按住空格或 Enter。删除后画布从列表消失，其他已打开页面会停止同步并保留本地内容供导出；旧页面的保存不会重新创建画布。如果删除请求与其他客户端修改发生竞争，删除可能被拒绝，可重试。

服务端将最新内容（包括尚未落盘的修改）与删除操作一起提交到 bare Git 仓库的 `trash/` 目录。文件名为 `UTC删除时间_画布ID.json`，例如 `20261025T153000.000000000Z_0123456789abcdef0123456789abcdef.json`。这是 Git tree 内的目录，无需工作副本。

服务启动时及之后每小时检查一次回收站，满 30 天的条目会通过新提交从当前 tree 删除；历史提交不改写。主页顶部可切换“我的画布 / 回收站”。回收站条目不可打开，点击恢复图标即可恢复到原画布 ID；恢复作为新的线性提交继续历史，不创建 fork，也不覆盖现存画布。原先因删除而停止同步的页面需刷新后继续编辑。管理员可用 `git --git-dir=/var/lib/drawsrv ls-tree HEAD:trash` 列出条目，用 `git --git-dir=/var/lib/drawsrv show HEAD:trash/文件名` 取出快照；过期后仍可从历史提交读取。

### 本地运行

需要 Go 1.24+、Git 2.36+ 和 make。仓库附带已构建的网页，运行时无需 Node.js 或 npm。

在仓库的 `drawsrv` 目录执行：

```sh
make build
./bin/drawsrv -static ./web/dist -data ./data
```

打开 <http://127.0.0.1:8080>。首次运行会创建数据目录；画布和历史都保存在其中。

### 部署到 VPS

在 Linux VPS 上准备好 Go、Git 和 make，然后执行：

```sh
make build
make deploy
sudoedit /etc/drawsrv/drawsrv.env
make enable
```

`make build` 只编译 Go，复用仓库中的静态网页。`make deploy` 安装程序、网页和 systemd 服务；`make enable` 启动服务。

使用独立域名，将整个站点反代到 `127.0.0.1:8080`，由反代提供 HTTPS 和身份认证。反代需支持 SSE 流式响应，且不要缓存 `/api/`。所有获准访问的人共享这些画布。

配置文件位于 `/etc/drawsrv/drawsrv.env`，数据默认保存在 `/var/lib/drawsrv/`。可参考[配置示例](deploy/drawsrv.env.example)调整监听地址、保存间隔和内存预算。修改配置后执行 `make restart`，用 `make status` 查看运行状态。

### 更新与备份

拉取最新代码后，在 `drawsrv` 目录执行：

```sh
make build
make deploy
make restart
```

已有配置和画布数据会保留。备份时先正常停止服务，再复制整个数据目录；恢复时将它作为服务的数据目录使用。

## 简要技术说明

前端使用官方 Excalidraw React 组件；Go 服务负责网页、保存和同步通知，无需数据库或 Docker。字体从公共 CDN 按需加载。

修改先暂存在服务端内存中，画布空闲 30 秒后落盘并记录 Git 历史；手动保存会立即落盘，正常退出也会保存待处理内容。异常中断仍可能丢失尚未落盘的修改。历史保存在数据目录的 bare Git 仓库中，可用 `git --git-dir=/var/lib/drawsrv log` 查看。

前端开发和 npm 构建在开发机器上进行：`make web` 更新网页，`make test` 运行测试。日常只提交源码，准备部署更新时才提交新的 `web/dist`。VPS 使用这些预编译网页，仅进行 Go 编译。
