# drawsrv 项目约定

## 环境与构建偏好

- VPS 资源有限，通常不安装或运行 Node.js/npm；仅进行 Go 编译，并由 Go 服务直接提供已有的网页静态资源。默认构建和部署流程应复用 `web/dist`，不触发 npm 构建。
- 开发机器资源宽裕，负责 npm 依赖安装、前端开发和构建。需要更新网页静态资源时，在开发机器执行 `make web`。
- npm 预编译结果（`web/dist`）默认不随日常源码修改提交到 Git。即使为了验证而重新构建，也不要顺带提交生成文件；仅在实际准备部署更新时，才更新并提交预编译结果，供 VPS 直接使用。

## 产品取舍（显式偏好）

- 保存与同步平时自动工作，详细状态只写控制台，不增加常驻保存/连接状态提示，避免打扰。
- 不提供 Git 历史恢复界面：本地撤销已覆盖日常需求，历史恢复在多客户端中有分叉/线性修改的语义负担。
- 暂不增加离线草稿恢复、复杂冲突处理或端到端浏览器测试；当前以网络通畅的个人跨设备使用为主。
- 编辑器不增加顶部返回入口，使用浏览器返回按钮、快捷键或手势。
- 列表不做缩略图，避免增加服务端复杂度。
- 字体不 check-in，避免撑大仓库；保留现有 CDN 方案。
- 支持列表删除画布；服务端自动将最新内容移入 Git tree 中单独的回收站目录，文件名包含删除时间。保留 30 天，服务端定期提交清理过期条目，仅修改当前 tree，不改写 Git 历史。
- 列表顶部切换“我的画布 / 回收站”。删除为行 hover 时显示的图标（触屏与键盘可访问），按住 1 秒以环形进度确认，松开/移出取消，不弹确认框；title tooltip 简要说明。回收站条目不可打开，恢复图标常显，点击直接恢复原画布 ID，沿用线性 Git 历史，不创建 fork。
- 画布列表行 hover 仅改变文字颜色，与顶部切换按钮一致，不改变背景；右侧图标的 hover 与交互行为独立保留。
- 当前多轮迭代期间不提交 web/dist；待明确准备部署时再更新并提交预编译资源。
